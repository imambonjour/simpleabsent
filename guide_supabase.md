# Panduan Setup & Integrasi Supabase

Dokumen ini berisi panduan langkah-demi-langkah untuk menyiapkan basis data di **Supabase** dan menghubungkannya dengan aplikasi.

## Setup Cepat Simple Absent

Form utama `index.html` menyimpan data ke tabel `absensi` dengan kolom nama, kelas, dan nomor absen.

1. Buka **SQL Editor** di Supabase.
2. Jalankan SQL berikut:

```sql
CREATE TABLE absensi (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    student_name TEXT NOT NULL,
    student_class TEXT NOT NULL,
    absent_number INTEGER NOT NULL CHECK (absent_number > 0),
    created_at TIMESTAMPTZ DEFAULT NOW()
);

CREATE INDEX idx_absensi_student_class ON absensi(student_class);
CREATE INDEX idx_absensi_absent_number ON absensi(absent_number);
CREATE INDEX idx_absensi_created_at ON absensi(created_at);
```

3. Copy `.env.example` menjadi `.env`, lalu isi placeholder:

```env
NEXT_PUBLIC_SUPABASE_URL=https://your-project.supabase.co
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=your-supabase-anon-or-publishable-key
ADMIN_PASSWORD=change-this-password
```

4. Generate config browser:

```bash
node scripts/generate-env.mjs
```

5. Buka `index.html` di browser. Jika Supabase belum terisi, halaman akan menampilkan placeholder setup.

Jika kamu mengaktifkan **RLS (Row Level Security)** untuk tabel `absensi`, tambahkan policy insert untuk role `anon`:

```sql
CREATE POLICY "Allow public attendance insert"
ON absensi
FOR INSERT
TO anon
WITH CHECK (true);
```

## 2. Setup Database Schema
Gunakan **SQL Editor** bawaan Supabase untuk membuat tabel dan fungsi RPC.

1. Buka menu **SQL Editor** di sidebar kiri Supabase.
2. Klik **New Query** (atau **Quick Start** lalu kosongkan).
3. Paste SQL query berikut untuk membuat tabel `siswa`, index pencarian, dan fungsi claim atomic:

```sql
-- 1. Buat tabel siswa
CREATE TABLE siswa (
    id TEXT PRIMARY KEY,               -- Menggunakan ID Siswa (format dari name.csv seperti 121_01)
    nama TEXT NOT NULL,
    qr_token UUID DEFAULT gen_random_uuid() UNIQUE NOT NULL,
    claimed BOOLEAN DEFAULT FALSE,
    claimed_at TIMESTAMPTZ,
    created_at TIMESTAMPTZ DEFAULT NOW()
);

-- 2. Buat index pencarian untuk optimasi performa query
CREATE INDEX idx_siswa_id ON siswa(id);
CREATE INDEX idx_siswa_nama ON siswa(nama);
CREATE INDEX idx_siswa_qr_token ON siswa(qr_token);
CREATE INDEX idx_siswa_claimed ON siswa(claimed);

-- 3. Buat Database Function (RPC) untuk Claim Konsumsi secara aman (Atomic)
-- Menghindari race condition ketika ada banyak panitia yang menscan bersamaan
CREATE OR REPLACE FUNCTION claim_konsumsi(token TEXT)
RETURNS TABLE(success BOOLEAN, nama TEXT, message TEXT)
LANGUAGE plpgsql
AS $$
DECLARE
    v_siswa RECORD;
    v_token_uuid UUID;
BEGIN
    -- Coba konversi input ke UUID jika valid
    BEGIN
        v_token_uuid := token::UUID;
    EXCEPTION WHEN others THEN
        -- Jika input bukan UUID valid, cek apakah ini ID Siswa biasa
        UPDATE siswa
        SET claimed = TRUE, claimed_at = NOW()
        WHERE id = token AND claimed = FALSE
        RETURNING siswa.nama INTO v_siswa;

        IF FOUND THEN
            RETURN QUERY SELECT TRUE, v_siswa.nama, 'Konsumsi berhasil dicatat'::TEXT;
        ELSE
            -- Cek apakah ID ada tapi sudah diclaim
            IF EXISTS (SELECT 1 FROM siswa WHERE siswa.id = token) THEN
                SELECT siswa.nama INTO v_siswa FROM siswa WHERE siswa.id = token;
                RETURN QUERY SELECT FALSE, v_siswa.nama, 'Konsumsi sudah diambil sebelumnya!'::TEXT;
            ELSE
                RETURN QUERY SELECT FALSE, ''::TEXT, 'QR Code / ID tidak valid!'::TEXT;
            END IF;
        END IF;
        RETURN;
    END;

    -- Proses pencatatan jika token berupa UUID valid (QR Token)
    UPDATE siswa
    SET claimed = TRUE, claimed_at = NOW()
    WHERE qr_token = v_token_uuid AND claimed = FALSE
    RETURNING siswa.nama INTO v_siswa;

    IF FOUND THEN
        RETURN QUERY SELECT TRUE, v_siswa.nama, 'Konsumsi berhasil dicatat'::TEXT;
    ELSE
        -- Cek apakah token ada tapi sudah claimed
        IF EXISTS (SELECT 1 FROM siswa WHERE siswa.qr_token = v_token_uuid) THEN
            SELECT siswa.nama INTO v_siswa FROM siswa WHERE siswa.qr_token = v_token_uuid;
            RETURN QUERY SELECT FALSE, v_siswa.nama, 'Konsumsi sudah diambil sebelumnya!'::TEXT;
        ELSE
            RETURN QUERY SELECT FALSE, ''::TEXT, 'QR Code tidak valid!'::TEXT;
        END IF;
    END IF;
END;
$$;
```
4. Klik tombol **Run** di kanan bawah. Pastikan status sukses (*Success. No rows returned*).

## 3. Hubungkan Aplikasi ke Supabase

### Langkah A: Ambil API Credentials
1. Buka menu **Settings** (ikon gerigi di kiri bawah dashboard Supabase).
2. Klik sub-menu **API**.
3. Cari bagian **Project API Keys** dan **Project URL**:
   - Ambil **Project URL** (contoh: `https://xyzabc.supabase.co`).
   - Ambil **`anon` / `public`** key (string panjang).

### Langkah B: Isi `.env` dan Generate Config Browser
1. Copy `.env.example` menjadi `.env` jika file `.env` belum ada.
2. Isi nilai berikut di `.env`:

```env
NEXT_PUBLIC_SUPABASE_URL=PASTE_PROJECT_URL_DISINI
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=PASTE_ANON_KEY_DISINI
ADMIN_PASSWORD=ganti-password-admin
```

3. Generate file config browser:

```bash
node scripts/generate-env.mjs
```

Perintah ini membuat `js/env.js`. File `.env` dan `js/env.js` tidak untuk dicommit.

Catatan penting: karena aplikasi ini static frontend, nilai di `js/env.js` tetap bisa dilihat browser saat sudah dideploy. Supabase anon key memang boleh public jika RLS/policies benar, tetapi password admin frontend hanya cocok untuk proteksi ringan acara internal.

### Langkah C: Aktifkan Script CDN Supabase

## 4. Setup Row Level Security (RLS) — Opsional tapi Direkomendasikan
Supabase secara default mengizinkan akses tulis jika RLS mati. Untuk mengamankan database agar tidak diutak-atik orang asing:

1. Buka menu **Database** → **Tables** → pilih `siswa` → Aktifkan **RLS (Row Level Security)**.
2. Tambahkan **Policies**:
   - **Policy 1**: Izinkan Siswa membaca datanya sendiri:
     - *Allowed operations*: `SELECT`
     - *Target roles*: `anon`
     - *Expression (USING)*: `true` (Semua orang boleh mencari/select datanya untuk memunculkan QR).
   - **Policy 2**: Izinkan import CSV & claiming:
     - *Allowed operations*: `INSERT` dan `UPDATE`
     - *Target roles*: `anon`
     - *Expression (WITH CHECK / USING)*: `true` (jika menggunakan database tanpa autentikasi login terpisah).
     
*Catatan: Karena sistem ini merupakan aplikasi panitia sederhana satu-kali-pakai, RLS dapat dibiarkan non-aktif jika dijalankan dalam jangka pendek saat hari H.*
